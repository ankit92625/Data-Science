Unit 1 — Intro to Data Science
by Mrs. Arnika Patel

💡 What is Data Science?

An interdisciplinary field — stats + algorithms + computing — used to dig knowledge & insights out of data (structured AND messy/unstructured).

Goals:

  • find hidden patterns
  • help decisions get made
  • predict what happens next
  • automate stuff w/ ML
  • = $$ business value

Used in:

  • 🏥 healthcare (disease predict)
  • 💰 finance (catch fraud)
  • 🛒 e-commerce (recs)
  • 📱 social media analytics
  • ⛅ weather + smart cities

= all the data being generated worldwide, all the time, from everything.

→ social posts, emails, videos, IoT sensors, transactions, apps... it never stops!

Unit 2 — Data Preprocessing
by Pallavi Sakalley

🧹 Why Preprocess?

Raw data is messy! Preprocessing = turning it into something a computer/model can actually use efficiently & accurately. Fixes inconsistent formats, human errors, missing bits.

Good data needs (5 factors):

  • Accuracy — is it actually correct?
  • Consistency — same answer every time
  • Completeness — no missing fields
  • Validity — right format/range/type
  • Timeliness — updated when the event happens

🛠️ The 4 Big Steps

Data Cleaning
→
Data Integration
→
Data Reduction
→
Data Transformation

Cleaning

fix incorrect/incomplete/missing values → handle missing values, de-noise

Integration

combine data from many sources → entity ID problem, schema integration, resolving conflicts

Reduction

shrink data size (save $ + storage) → dimensionality reduction, numerosity reduction, compression (lossy/lossless)

Transformation

reshape data for ML → smoothing (remove noise), aggregation (summarize e.g. daily→monthly), discretization (numbers→bins e.g. age→"young/old"), normalization (scale to [0,1] etc.)

💭 remember: normalization = squish numbers into a standard range so no one feature "dominates" the model!

📥 Reading & Selecting Data

Reading data = importing/loading it into your DS environment — the foundation everything else is built on. (same 3 types as unit 1: structured / unstructured / semi-structured)

Selecting data = picking the relevant subset you actually need. Key things to check:

  • Relevance — does it relate to the question?
  • Validity, Completeness, Quality
  • Dimensionality — too many features = trouble
  • Balance — represent all classes fairly
  • Size vs. compute cost tradeoff

🔍 Filtering Data

Keep only the rows/values that meet a condition — cuts noise, focuses the analysis.

  • by condition: numerical / text / categorical
  • by rows or columns
  • by data quality
  • by time

Filtering missing values (super common!):

Remove  |  Impute (mean/median/mode)  |  Interpolate (for time series)

✋ Manipulating Data

cleaning + reshaping + aggregating + merging, all rolled together.

  • Cleaning — drop_duplicates(), regex for text errors
  • Transformation — scaling/normalizing, label encoding, one-hot encoding
  • Aggregation — group + summarize stats
  • Feature engineering — build new useful features

↕️ Sorting, Grouping, Ranking

OpWhat it does
Sortingarrange asc/desc by 1+ columns (single or multi-level)
Groupingbucket rows + aggregate → find patterns/trends
Rearrangingreshape/wrangle overall — clean+reshape+subset+sort+merge+group+engineer
Rankingassign order by criteria — simple, percentile, weighted, time-series, tie-break
basically Unit 2 = "get the data ready before you dare touch a model" 🧽

🧮 Normalization — the actual formulas

MethodFormulaResult range
Min-Maxx' = (x − min) / (max − min)[0, 1]
Standardization (Z-score)x' = (x − mean) / std_devmean 0, unit variance

→ use Min-Max when you know the bounds; use Z-score when data has outliers/is roughly normal.

🗂️ Data Reduction — a closer look

  • Dimensionality Reduction — drop/combine less-useful features (e.g. PCA) so models train faster + avoid the "curse of dimensionality"
  • Numerosity Reduction — represent data with a smaller model or sample instead of the full set (e.g. regression models, histograms, clustering)
  • Data Compression — lossless (nothing lost, e.g. ZIP) vs lossy (some detail lost but way smaller, e.g. JPEG)

Unit 3 — Concept Learning
by Ms. Shivangi B. Patel

🧠 What is Concept Learning?

ML approach where the system learns a concept from examples, then decides if a NEW example belongs to that target class.

→ classic example: "is this day good for playing tennis?" based on weather/temp/humidity/wind

TermMeaning
Instanceone input example
Attributea property of the data
Hypothesisa possible rule describing the data
Target Conceptthe actual thing being learned

👍 Pros

  • learns straight from examples
  • better prediction accuracy
  • less manual rule-writing
  • generalizes to new cases
  • base of supervised learning

👎 Cons

  • hates noisy data
  • hypothesis space explodes fast
  • can be $$$ computationally
  • needs labeled data
  • can overfit
  • struggles w/ continuous data

used for: spam filters, medical diagnosis, Netflix/Amazon recs, fraud detection, image/speech recognition...

❓ Hypothesis Basics

a clear testable statement predicting a relationship btwn variables.

TypeExample
Null (H₀)"study hours don't affect marks"
Alternative (H₁)"study hours improve marks"
Simple"exercise reduces stress"
Complex"diet + exercise improve health & productivity"

steps: identify problem → review literature → identify variables → find logical link → write clear testable statement

🎯 PAC Learning

Probably Approximately Correct — a framework for math-checking how good an ML algorithm's generalization is.

Goal: with high probability ("Probably"), the learned hypothesis has low error ("Approximately Correct")
  • ε (epsilon) = max allowed error → Accuracy = 1 − ε
  • δ (delta) = probability of failure → Confidence = 1 − δ

formally: P( error(h) ≤ ε ) ≥ 1 − δ

→ smaller ε & δ = stricter requirement = harder to satisfy!

📐 VC Dimension

measures how complex/powerful a model is — "max # of points a classifier can perfectly shatter" (get every possible labeling right).

ModelVC Dim
Point classifier1
Line in 2D3
Circle in 2D3
Neural netsvery high
high VC dim → overfitting risk 😬
low VC dim → underfitting risk 😴

🗑️ Hypothesis Elimination & Version Space

Start with ALL possible hypotheses (H) → toss out any that conflict w/ training data → keep only the consistent ones = Version Space (VS).

S (Specific boundary) — most specific hypothesis, covers only the positives seen so far

G (General boundary) — most general hypothesis, covers as much as possible w/o including negatives

→ true version space sits between S and G!

⚙️ Candidate Elimination Algorithm

Init S=most specific, G=most general
→
example is + : generalize S, trim G
→
example is − : specialize G, trim S
→
repeat till S = G (done!) or disjoint (data inconsistent)

quick worked example

#ColorShapeSizeClass
1RedCircleSmall+
2GreenCircleMedium−
3RedTriangleSmall+

S starts [Red,Circle,Small] → ex.2 is negative so G specializes to exclude Green/Circle/Medium → ex.3 is positive so S generalizes to [Red, ?, Small]. Keep going till S,G converge!

✅ pros: systematic, guarantees target concept found (if data is clean)
⚠️ cons: expensive for big hypothesis spaces, hates noisy data

🔢 PAC Learning — worked-through example

Say ε = 0.1 and δ = 0.05:

  • Accuracy required = 1 − ε = 1 − 0.1 = 90% accurate
  • Confidence required = 1 − δ = 1 − 0.05 = 95% confident

→ in plain English: "I want a hypothesis that's at least 90% accurate, and I want to be 95% sure I got one like that."

smaller ε or δ = a *stricter* requirement = usually needs MORE training examples to satisfy

📏 VC Dimension — shattering example, step by step

For a linear classifier (a line) in 2D, try to shatter 3 points:

  • 3 points → 2³ = 8 possible label combos
  • a line CAN separate all 8 combos → shattered! → VC dim ≥ 3

Now try 4 points arranged e.g. in a square (XOR-style labeling):

  • no single straight line can separate the "diagonal" labeling correctly
  • → can't shatter 4 points → VC dimension of a line in 2D = 3

🧩 Version Space — finishing the worked example

Continuing the Color/Shape/Size example from before, after all 3 training examples:

BoundaryValue after processing
S (specific)[Red, ?, Small]
G (general)[Color ≠ Green, ?, ?] (refined, consistent with all examples)

→ if more examples come in and eventually S = G, that single hypothesis IS the learned target concept. If S and G ever become empty/disjoint, the training data itself is contradictory (noisy).

Concept learning = find h ∈ H such that h(x) = C(x) for all x
PAC: P(error(h) ≤ ε) ≥ 1 − δ

📌 Candidate Elimination — Algorithm Pseudocode (write exactly like this in exam!)

1. Initialize S = {most specific hypothesis in H}
2. Initialize G = {most general hypothesis in H}
3. For each training example d:
  If d is positive:
    Remove from G any hypothesis inconsistent with d
    Generalize S minimally to be consistent with d
  If d is negative:
    Remove from S any hypothesis inconsistent with d
    Specialize G minimally to be consistent with d
4. Repeat until S = G (converged) or S, G disjoint (inconsistent data)
